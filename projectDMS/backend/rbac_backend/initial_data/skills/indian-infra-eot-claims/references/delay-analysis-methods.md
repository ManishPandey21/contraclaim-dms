# Recognised Delay Analysis Methods

Prefer these industry-standard methods and state which one is used:

1. **Time Impact Analysis (TIA)** – Insert a fragnet representing the delay event into the updated programme and recalculate the completion date. Best for prospective or contemporaneous analysis.

2. **Windows Analysis** – Divide the project into sequential time windows and analyse critical path changes within each window. Good for complex, long-running projects.

3. **As-Planned vs As-Built** – Compare the baseline programme with the actual as-built programme to identify variances. Simple but can be less precise on causation.

4. **Collapsed As-Built / But-For Analysis** – Remove Employer-responsible delays from the as-built programme to show what the completion date would have been.

Document assumptions, programme version used, and any logic changes made.
